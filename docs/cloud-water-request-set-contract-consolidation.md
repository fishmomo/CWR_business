# 云水资源请求集契约收敛记录

状态：2026-08-30 完成并截止。

## 目标

将单年和多年云水资源请求集重复的协议与准备逻辑收敛为公共接口，同时保持既有
公式、统计、图件、模板、报告文字、产物内容和用户时段语义不变。

## 公共接口

`src/cwr_engine/workflows/cloud_water_request_contract.py` 统一负责：

- 请求集顶层字段、共享数据源、必要区域和年度/月度成员的严格校验；
- 共享字段合并为标准 `BusinessRequest` 输入；
- 报告产品字段、模板路径、报告文件名和图片宽度解析；
- 产品源与内部区域格式转换；
- 带时间坐标的数据集拼接和 `PreparedNetcdfSource` 构造；
- `mask_bundle.json` 的生成与元数据写出；
- prepared dataset 驱动的标准请求执行。

单年和多年模块继续分别负责不同的时段约束、年度准备循环、专题派生和报告组装，
不为追求形式统一而合并不同业务行为。

## 兼容政策

- `cwr-engine --request` 是单年和多年报告的权威入口，后续新能力优先扩展该入口。
- 本阶段完成时，`cwr-engine --workflow-spec` 作为兼容入口继续可用且不再扩展。
- 后续退役阶段已获得用户明确批准，并于 2026-08-31 将示例和文档迁移至
  `--request` 后删除该入口；历史 workflow 配置应改写为对应请求集。

## 验收

- 单年和多年请求集专项测试：44 项通过。
- 共享契约直接测试：3 项通过。
- 完整测试：135 项通过，运行环境为 `cwr_py312`。
- 真实单年 2025 请求生成 5 幅图和 1 份 DOCX。
- 真实多年 2021-2025 请求生成 6 幅图和 1 份 DOCX。
- 正式 JSON 中 staging 或临时目录引用为 0。
- 指标 JSON、空间 NetCDF 和全部 11 幅图与兼容基线逐字节一致。
- 两份 DOCX 的全部 OOXML 部件与兼容基线一致。
